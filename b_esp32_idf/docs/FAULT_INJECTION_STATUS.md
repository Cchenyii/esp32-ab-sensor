- 10 次有完整时间记录的实物恢复全部通过：STM32 重启 4 次、B 重启 3 次、A 暂停 12 秒后恢复 3 次。

## 正式 60 秒基线

- 275 帧已接受摇杆日志、30 帧传感器日志、60 次传感器回传 ACK、60 次心跳。
- 同一会话的已记录摇杆序号没有缺口；不能据此给出无线或串口总体丢包率。
- UART 统计样本首尾窗口为 50130ms：错误、重复、拒绝、重试和失败增量均为 0。
- A→B 网络统计窗口为 50055ms：CRC/协议拒绝、序号缺口、ACK 错误和超时增量均为 0。
- 上述统计窗口由 10 秒一次的计数日志确定，不等同于整个 60 秒捕获范围。先导 60 秒基线另有 274 帧摇杆、30 帧传感器和 60 次回传 ACK，保留在原始记录中。

## 实物恢复时间

统计只给最小值、中位数、最大值；样本量较小，不计算 p95/p99。

### STM32 重启

- CLI 命令发起至摇杆首帧（n=4）：最小 406 / 中位 406.5 / 最大 407 ms。各次：406, 406, 407, 407 ms。
- B 握手完成至摇杆首帧（n=4）：最小 7 / 中位 7 / 最大 7 ms。各次：7, 7, 7, 7 ms。
- 4 次均换新会话，并接受 seq=1；握手完成到首帧按 B 自身日志计时。完整恢复从 CLI 命令发起计时，包含连接探针的开销。

### B 板重启

- EN 释放请求至摇杆首帧（n=3）：最小 1015 / 中位 1046 / 最大 1266 ms。各次：1015, 1046, 1266 ms。
- EN 释放请求至有效传感器 ACK（n=3）：最小 10156 / 中位 10187 / 最大 10328 ms。各次：10187, 10156, 10328 ms。
- EN 释放请求至 MQTT 连接（n=3）：最小 14922 / 中位 15328 / 最大 45671 ms。各次：15328, 45671, 14922 ms。

### A 板暂停 12 秒

- 暂停请求至失效状态 ACK（n=3）：最小 2297 / 中位 4750 / 最大 5454 ms。各次：5454, 2297, 4750 ms。
- 恢复请求至有效传感器 ACK（n=3）：最小 3766 / 中位 3797 / 最大 3797 ms。各次：3797, 3766, 3797 ms。
- 每次暂停期间仍观察到 55 帧摇杆和 12 次心跳；传感器先标为无效，恢复后重新收到有效回传 ACK。失效可能由 TCP 断开或数据过期触发。

## 电脑模拟故障

模拟时钟结果仅用于验证重试与状态机，不能写成硬件响应延迟。

- 丢第一次握手 OFFER：2 次 REQUEST 后成功；丢第一次确认 ACK：2 次 CONFIRM 后成功。两者的模拟等待均为 150ms。
- ACK 前加入噪声、错误序号、旧 token 和坏 CRC：仍识别正确 ACK，坏 CRC 拒绝计数为 1。
- 一帧的 ACK 均不匹配：本帧发送 3 次，模拟等待 360ms 后报失败。
- 连续 3 帧都失去 ACK：累计 9 次失败发送、模拟等待 1080ms，清除会话后重新握手并从 seq=1 恢复。
- 重复与旧传感器帧：3 次 ACK，业务缓存只更新 1 次；序号跨尾后保持正常去重。
- 传感器过期：模拟推进 4001ms 后 valid=false，同时保持链路存活。
- FIFO 注入 512 字节：触发 1 次溢出、1 次接收重启，丢弃受损缓冲后重新收到 17 字节。
- 注入 UART ORE/DMA 错误：错误计数各增 1，TaskB 路径重启接收 1 次；接收重启第一次失败时保留重试标志，随后成功。
- 固定种子 0x20261014：2000 轮 DMA 分片，198816 字节接收与消费一致，无模拟 FIFO 溢出。

## 资源收尾样本

STM32 的 DMA 为循环模式，USART2 DMAR 与 IDLE IRQ 启用。
收尾读数：received=consumed=27125，FIFO 溢出、UART/DMA 错误、接收重启均为 0。
FIFO 峰值 39/511 字节；TaskA/TaskB 栈最小剩余分别为 1316/1268 字节（各分配 2048）；最小可用堆 10848 字节。
成功 ACK 的单次等待累计最大值为 27ms，是最近 STM32 复位以来的样本。没有测量 CPU 利用率。
B 各次启动报告的 minimum_heap_bytes 最小值为 107396 字节。
